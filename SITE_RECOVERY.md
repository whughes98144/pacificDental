# Site source recovery — Pacific Dental Alliance

## Ownership and rights

The site operator has stated they **own Pacific Dental Alliance and all rights to the images and content**, and that the original deployment source was lost. This recovery reproduces the **public static surface** of [https://www.pacificdentalalliance.com/](https://www.pacificdentalalliance.com/) from the live server as of the recovery run, for hosting on GitHub Pages and future maintenance.

## What was recovered

| Area | Status |
|------|--------|
| Home, Our Story (`/about/`), Locations index, Group Programs, Contact | Full HTML, layout, and copy |
| Location detail pages | All practice “Details” pages linked from the locations index (static list on the live site) |
| CSS, JS, Bootstrap, jQuery, Open Iconic, logos, marketing JPEGs | Downloaded into `docs/_assets/` |
| Favicon | `docs/favicon.ico` |

A machine-generated fetch inventory (every URL attempted, HTTP status, content-type) is in **`SITE_RECOVERY_LOG.md`**.

## What is not static / known gaps

1. **`photoviewer.ashx` (doctor photos, some hero backgrounds)**  
   These are generated by **ASP.NET on the original host** and return errors when requested as static files. In this recovery, all `photoviewer.ashx` references in HTML were rewritten to **absolute URLs on the production domain** so images still load **as long as that endpoint remains available**. To make the GitHub Pages copy fully self-contained, export those images from the old CMS or database and replace the URLs with files under `docs/_assets/`.

2. **Contact form**  
   The contact page is a `POST` form to the legacy server. **GitHub Pages cannot run server-side handlers.** Replace with a static form service (e.g. Formspree, Netlify Forms), an email link, or a hosted app.

3. **Google Maps on location pages**  
   The recovered pages include a **Google Maps JavaScript API key**. Ensure [API key restrictions](https://developers.google.com/maps/documentation/javascript/get-api-key) allow your GitHub Pages URL (or your custom domain), or maps may fail to load.

4. **Google Analytics**  
   The same GA property (`UA-128068516-1`) is embedded as on the live site. Update or remove if you use a different property for the GitHub-hosted copy.

5. **Open Iconic `.otf`**  
   The live server returned **500** for `open-iconic.otf`. WOFF/SVG/TTF are present; layout should be fine.

6. **Admin / secure URLs**  
   Crawling intentionally **skips** paths under `/secure/`, `/account/`, `/_review/`, `/error/`, and `photoviewer.ashx` as crawl targets (per `robots.txt` and because they are not static). A stray admin link may have appeared in an earlier crawl log before filters were added; it is not part of the public site.

## How to re-run recovery

Requires Python 3 and network access.

```bash
python3 scripts/recover_site.py
```

This refreshes `docs/`, rewrites root-relative URLs to **relative** paths for portable hosting, runs `scripts/fix_photoviewer_urls.py`, and regenerates `SITE_RECOVERY_LOG.md`.

To apply only the photoviewer URL fix after manual HTML edits:

```bash
python3 scripts/fix_photoviewer_urls.py
```

## GitHub Pages

1. Push this repository to GitHub.  
2. **Settings → Pages → Build and deployment**: source **Deploy from a branch**, branch **`main`** (or default), folder **`/docs`**.  
3. `docs/.nojekyll` is present so Jekyll does not ignore the `_assets` directory.

Published URL shape: `https://<user>.github.io/<repo>/` — relative links in `docs/` are compatible with that path prefix.
